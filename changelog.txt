# Changelog

### 1.1.3 - 2026-10-28

#### Security
* Uploaded files were listed by WordPress's public media REST endpoint, because attachments were created without a parent and in the "inherit" status. Visitor uploads are now stored as private attachments.
* Values typed into block style controls (sizes, gradients, font stacks, shadows, transitions) could carry CSS syntax into the inline stylesheet, so anyone able to save a post with the block could inject site-wide CSS. Those values are now sanitised as CSS, and anything that could break out of a declaration is dropped.
* Sending an array where a text value was expected caused an unauthenticated PHP 8 fatal error (HTTP 500). Submissions are now shape-checked before validation, with per-type length caps (text 1000, textarea 20000, email 254, URL 2048 characters, adjustable with the neural_forms_max_field_length filter) and a 200-item cap on multi-value fields. This also closes a storage and AI-credit exhaustion vector.
* The block's editor-preview branch could be reached through anonymous REST reads of a post and rendered draft or archived forms. It now also requires the edit_posts capability.
* Log files had a guessable location under uploads and only an Apache 2.2 deny rule. File names now include a per-site random token, and the directory also carries an Apache 2.4 deny rule.
* Changing settings, testing or revoking the Cloud connection, sending the test email and running the AI queue by hand now require the manage_options capability. Reading settings is unchanged.
* Autoresponder tokens are expanded in a single pass, so a submitted value that itself contains a token such as {other_field} is no longer expanded.
* The submission rate limit could be bypassed with a forged X-Forwarded-For header: any value, even a non-IP, either rotated the bucket or disabled the limit. The client IP is now the connecting address unless it belongs to a proxy declared through the new neural_forms_trusted_proxies filter (IPs or CIDR ranges, IPv4 and IPv6). Behind a trusted proxy, CF-Connecting-IP is honoured first, then X-Forwarded-For is walked from the right-most untrusted hop. The same IP feeds CAPTCHA verification and the IP stored on each entry.
* The rate limit is now counted per form and IP rather than per IP across the whole site. The honeypot runs before the limiter, so bot traffic no longer uses up attempts shared by real visitors on the same IP. A request without a usable client address is no longer exempt and shares one bucket. The neural_forms_rate_limit filter now receives the form ID as a fourth argument.

#### Privacy
* Privacy mode did nothing. The setting existed and could be saved, but nothing read it on submission, so entries always stored the visitor's IP address and user agent, including on sites that told visitors they did not. With the toggle on, both are now left blank. The IP is still used in memory for the rate limit and CAPTCHA verification, but never stored. On update, sites that already have Privacy mode on get the IP and user agent cleared from their existing entries once (database version 1.1.3). Sites with it off are untouched.
* New: WordPress's Export Personal Data and Erase Personal Data tools now cover Neural Forms entries, matched by the submitted email address. The export lists every stored field plus the IP, user agent and page URL where present. The eraser removes the entries, their message threads, AI drafts and uploaded files. Suggested privacy-policy text is added under Settings > Privacy > Policy Guide.

#### Forms and builder
* Help text written in the builder was saved and previewed but never shown on the live form. It now appears under the input for every field type and is linked to the input for screen readers.
* File Upload fields had no builder controls for their limits even though the server enforced them. The inspector gains "Allowed file types" (Images, PDF, Documents, Text) and "Maximum file size (MB)", capped at the host's upload limit. The builder preview names the extensions instead of group ids.
* File size limits ignored the host's PHP limit (often 2 MB), so a 3 MB file passed the "Max 5 MB" hint and then failed with a generic upload error. The effective limit is now the lower of the field setting and the server limit, used by the hint, the browser check and the server check alike. Oversized files get a clear size message, and a request larger than PHP's post limit returns a size error instead of "required" errors for every field.
* Field IDs were invisible in the builder although the email help told users to use them in templates. The inspector now shows a read-only Field ID row with a Copy token button, and the Settings hints explain where to find it.
* A required field hidden by conditional logic still blocked submission with "X is required", and no entry was saved. Hidden fields, and fields whose controlling field is hidden, are now removed from server-side validation. Conditions that depend on an unticked single checkbox or an unchecked radio are evaluated the way the browser evaluates them, so "is empty", "is not empty" and "equals" rules agree on both sides.
* Multi-step forms: on the last step, the Previous and Submit buttons stacked on two lines. They now share one row, Previous on the left and Submit on the right, and only stack on narrow screens. The button markup is unchanged, so existing block and Divi styling still applies.
* With labels hidden (the block default), validation messages named the placeholder, for example "Jane Cooper is required", and radio, checkbox, rating, matrix and repeater groups lost their question entirely. Text-like fields now always get a label, visible or screen-reader-only, and choice groups and file fields always show theirs.
* An optional Phone field left untouched blocked the Next button and the final submit with "must be a valid phone number", because the country picker pre-fills the dial code. A value that is only a dial code now counts as empty in the browser, on the server and in the stored entry. A required Phone left empty now says "is required".
* Quiz and poll "Randomize options" had no effect. Options are now shuffled on the server, so it works without JavaScript, and reshuffled on every page load so page caches do not freeze a single order.
* Styled blocks caused a fatal error on PHP 7.4 hosts because of a PHP 8-only type hint, although the plugin supports 7.4. Fixed.

#### Emails
* Replies sent from the inbox ignored Email Settings and went out as "WordPress <wordpress@domain>". They now use the configured sender, a matching Reply-To and a plain-text content type, and the stored message records the real sender address.
* The "Default reply subject" setting was saved but never used; replies always had the subject "Re: Your submission". It is now the default subject, with {site_name} and {form_name} tokens, and the reply composer has an editable Subject field.
* A form's own Notification email and "Send admin notification" setting were saved but never read, so every form notified the global address. The per-form address is now the first choice, and the per-form toggle overrides the global one when it has been set. Forms that never set it behave as before.
* Email Settings promised that a blank Sender name uses the site title and a blank Sender email uses the WordPress admin email, but no From header was sent unless a valid Sender email was set, and a Sender name on its own was dropped. Those defaults now apply to notifications, autoresponders, replies and the test email alike.
* Notification emails and the inbox showed option values ("laptop") instead of their labels ("Laptop"), and checkbox groups appeared as a JSON array. Labels are now shown in the admin notification, autoresponder tokens and the inbox. CSV export keeps the raw values on purpose, so spreadsheets stay stable.
* Autoresponder tokens were only applied to the body. They now work in the subject line too.
* The "View entry" link in admin notification emails and in the quiz attempts analytics table opened the entries list instead of the entry.

#### Entries inbox
* The list stopped at 50 rows with no way to reach older entries. A "Load more" control appends the next 50 until every entry matching the current view is shown, with a "Showing X of Y" count.
* Searching for accented names such as "José" or for web addresses found nothing, because entry data was stored with escaped JSON. New entries are stored unescaped, and the search matches both forms so older entries are found too. CSV export with a search term behaves the same way.
* Keyboard shortcuts acted on an invisible focused row that never followed the entry you opened, so opening entry 5 and pressing # could trash entry 1. Shortcuts now target the open entry, or the highlighted row, which is visibly marked and scrolls into view. Trash and spam from the keyboard close the detail like the toolbar buttons do, and Escape no longer navigates back twice.
* Bulk actions drop nested arrays in the ID list (which previously resolved to entry #1) and cap a batch at 500 entries. The "already processing" check no longer matches entry 12 against a job for entry 123. The "filtered by safety" AI state is now stored as such instead of as failed.

#### Import
* Contact Form 7 import: placeholders were imported as pre-filled values; acceptance checkboxes were imported as optional although CF7 makes them required by default; size limits such as 2mb were dropped and byte values were copied straight into the MB field; allowed file types were stored as a string the upload check ignored; and numeric defaults on radio, select and checkbox fields were kept as the literal number instead of the option. All five now import correctly. Dynamic CF7 defaults such as the current user's email are left empty.
* The readme and the Import screen described a "Migration" page and a "Scan for CF7 Forms" button that do not exist. The screen is Neural Forms > Import and lists forms directly. The preview now notes that labels come from CF7 tag names, not from the form's visible label text.

#### Other fixes
* PHP 8 notices in form decoding, rendering, notifications and the admin asset manifest. A warning printed before the status header corrupts the HTTP status on hosts with display_errors on.
* A cron AI batch updating plan usage could resurrect an API key an administrator had just revoked, because settings were merged from a stale copy.
* The message shown when a poll or quiz reaches the free submission limit, and the Page Performance upsell in Analytics, linked to a page that does not exist. Both now point to the pricing page.
* Uninstall also removes the template-import record, the log token and the template-catalog transients.
* The free plugin's AI wording was inconsistent between the readme, the builder and Settings. All three now say the same thing: any entry can be analysed once from the inbox with a free API key; automatic analysis of new submissions, re-analysis, regenerate and polish are part of Neural Forms Pro.

### 1.1.2 - 2026-07-01

#### Fixed
* Multi-step forms no longer trigger an auto-scroll on page load.
* WordPress.org plugin directory now lists all four blocks (Form, Poll, Quiz, Multi-step).
* Field labels in the entry inbox no longer show raw slugs when a form was built without labels.
* "Analyze with Neural AI" now works on Lite installs without needing Pro.

#### Improved
* Form builder's Active status pill restyled — blue background with mint text.
* Clearer setup notices in the entry inbox — guide users to Settings when the API key or Neural AI toggle needs attention.
* Locked features in Lite now show a direct upgrade or setup link instead of a generic error.

### 1.1.1 - 2026-06-23

#### Fixed
* Front-end form assets (form-submit.js, form.css) were missing from the WordPress.org package, so form submission did not work for installs from WordPress.org. The assets are now included.

### 1.1.0 - 2026-06-22

#### Added
* Multi-step forms for breaking long forms into manageable steps.
* Poll block and multi-step form block for the block editor.
* Ready-to-use form templates so you can start with a working form in one click.

#### Improved
* Form dashboard layout for easier navigation.
* Form builder with smoother drag and drop.
* Inbox layout for faster scanning of submissions.

### 1.0.0 - 2026-06-21

#### Added
* Visual form builder with 16 field types, live preview, and validation.
* Lead inbox with status management, search, filters, and CSV export.
* AI auto-analysis via Neural Forms Cloud with summary, priority, and draft reply.
* Email notifications and customer auto-responder.
* Cloudflare Turnstile and Google reCAPTCHA v2 support.
* Privacy mode toggle for GDPR-friendly submissions.
* Contact Form 7 one-click import.
