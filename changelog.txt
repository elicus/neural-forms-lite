# Changelog

### 1.1.3 - 2026-10-27

#### Security
* **Privacy: Privacy mode did not work.** `privacy_mode` existed in Config / Settings but nothing read it on submission, so entries always stored the visitor's IP address and full user agent — including on sites that told visitors they did not. `SubmitEndpoint` now blanks both (and the IP in the CAPTCHA-failure log) when the toggle is on; the IP is still used in memory for the rate limit and CAPTCHA verification but never persisted. On upgrade, sites with Privacy mode ON have `ip_address` / `user_agent` blanked on all existing entries once (`Database::scrub_visitor_metadata()`, DB version 1.1.3). Sites with it off are untouched.
* Submission rate limit could be bypassed with a forged `X-Forwarded-For` header (any value, even a non-IP, either rotated the bucket or disabled the limit). The resolved client IP is now `REMOTE_ADDR` unless it belongs to a proxy declared via the new `neural_forms_trusted_proxies` filter (IPs or CIDR ranges, IPv4/IPv6). Behind a trusted proxy, `CF-Connecting-IP` is honoured first, then `X-Forwarded-For` walked from the right-most untrusted hop. The same resolved IP feeds CAPTCHA verification and the IP stored on each entry, so those can no longer be forged either.

#### Added
* WordPress privacy tools: Neural Forms now registers a personal-data **exporter** and **eraser** (Tools > Export / Erase Personal Data) that find entries by the submitted email address — the export lists every stored field plus IP / user agent / page URL when present; the eraser deletes the entries and their message threads and AI drafts. Suggested privacy-policy text is added under Settings > Privacy > Policy Guide (`wp_add_privacy_policy_content`). New module `modules/privacy/PrivacyTools.php`.

#### Fixed
* Emails and the entry inbox showed select / radio / checkbox VALUES ("laptop") instead of the option LABELS ("Laptop"); checkbox groups rendered as a JSON array in the inbox. New `NotificationService::display_choice()` + JS `formatChoiceValue()` map stored values to labels in the admin notification, autoresponder tokens, the Submitted fields card and the conversation text. CSV export keeps raw values on purpose (stable for spreadsheets).
* Autoresponder tokens (`{site_name}`, `{form_name}`, `{field_id}`) were only applied to the body; the subject is now rendered too (line breaks stripped).
* Field IDs were invisible in the builder although the autoresponder help told users to use them: the inspector now shows a read-only "Field ID" row with a "Copy token" button, and the Settings hints explain where to find it. (The per-form "Send admin notification" box, also reported, was fixed earlier in 1.1.3.)
* Inbox replies ignored Email Settings: `ReplyEndpoint` called `wp_mail()` with no headers, so replies went out as "WordPress <wordpress@domain>" while notifications and the autoresponder used the configured sender. Replies now carry the same From (via `NotificationService::build_from_headers()`, with the site-title / admin-email defaults), a matching Reply-To, and a plain-text Content-Type; the stored outgoing message records the real sender address.
* "Default reply subject" (Email Settings, `reply_subject_pattern`) was saved but never used — the endpoint hard-coded "Re: Your submission" and the composer sent no subject. The endpoint now defaults to the setting (with `{site_name}` / `{form_name}` tokens), and the reply composer gains an editable Subject field pre-filled from it.
* Contact Form 7 import (`CF7Detector` / `CF7FieldMapper`): (a) `[text* your-name placeholder "Jane Cooper"]` imported the text as `default_value` — CF7's `placeholder` is a bare flag and the text is the tag value; it is now the placeholder and the default stays empty. (b) `[acceptance privacy]` imported as optional — CF7 acceptance is required unless `optional`. (c) `limit:2mb` / `limit:500kb` were dropped (`get_option('limit','int')` only matched digits) and a bytes value like `limit:1048576` was copied straight into the MB field; limits now go through CF7's `get_limit_option()` and are converted to whole MB (rounded up). (d) `filetypes:pdf|docx` was copied as a string the upload check ignores; it is now mapped to the plugin's type groups (image / pdf / document / text, incl. `image/*`). (e) `default:1` on radio / select / checkbox is resolved to the option value(s) (`default:1_3` → both) instead of the literal "1". Dynamic CF7 defaults (`user_email`, `get`, `post`…) are left empty.
* Readme / Import screen: the FAQ said "Neural Forms > Migration" + "Scan for CF7 Forms"; the screen is "Neural Forms > Import" and lists forms directly. The preview now notes that labels come from CF7 tag names, not from the form's label text.
* Dead upgrade links: the poll / quiz 200-submission limit error (`upgrade_url`) and the Analytics Page Performance upsell pointed at `https://neuralforms.ai/pro/`, which returns 404. Both now use `https://neuralforms.ai/pricing/` like every other upgrade link in the plugin.
* Conditional logic: a required field hidden by a condition still blocked submission — Step 5a stripped the hidden field's value but left the field in the validated schema, so the server returned "X is required." for a field the visitor could not see and no entry was saved. Hidden fields are now removed from the validated schema as well (new `resolve_hidden_field_ids()`, which also hides fields whose controller is hidden). Choice controllers are evaluated like the browser does: an unticked single checkbox (not posted on the multipart path, posted as `0` by the JS serializer) and an unchecked radio now count as empty, so "is empty" / "is not empty" / "equals" rules on a checkbox agree between client and server; previously the server saw `'0'` as non-empty and either validated a hidden required field or stripped a value the visitor had filled in.
* Multi-step forms: on the last step, Previous and Submit stacked on two lines (the nav row held Previous / Next, the submit button lived in its own block below). The nav row and the submit wrapper now sit in a flex `.neural-forms-form__steps-footer`, so the last step shows Previous left / Submit right like every other step. Markup of the nav and submit wrapper is unchanged, so block / Divi scoped CSS keeps applying; below 600px the footer stacks.
* Copy: the free plugin's AI story was told two different ways. The readme said "AI analysis on every submission", while the builder's Process with AI panel said "Neural AI processing requires Neural Forms Pro". The actual behaviour: Lite can analyze any entry once, on demand, from the inbox (free API key + credits); automatic analysis of every new submission (`ai_process_entries`), re-analysis, regenerate and polish are Pro. The builder notice, the Settings "Auto-process entries" hint (which was an ungated no-op in Lite) and the readme now all say exactly that.
* Hidden labels (block "Show labels" off, the default): (a) required / type errors named the placeholder — "Jane Cooper is required." — because no label element was rendered and `form-submit.js` fell back to the placeholder; text-like fields now always get a `<label>`, visible or `.screen-reader-text`, which also gives assistive tech a real accessible name, and `fieldLabelText()` reads it. (b) Radio, checkbox, rating, matrix and repeater groups rendered their question as a screen-reader-only legend, so "Ticket type" above three radios was simply missing; those types (and file fields) now always show their label, matching poll / quiz, since they have no placeholder to carry it. The block default stays off — flipping it would change the layout of every existing block that never saved the attribute.
* Phone field: an optional Phone left untouched blocked multi-step "Next" (and final submit) with "must be a valid phone number", because the country picker pre-fills the dial code ("+1") so the value was never empty and failed the 7-digit rule. A value that is only a dial code now counts as empty in `form-submit.js`, in `SubmissionValidator` (new `normalize_phone()`), and in the stored entry (`''` instead of `"+1"`). A required Phone left untouched now says "is required" instead of the type error.
* Per-form Settings > Notifications were saved but never used: the builder stores `settings.admin_notification_email` / `settings.enable_admin_notification` on the form row, while `NotificationService` only read `form_schema.settings.admin_notification_email` and the legacy `settings.notification_email`, and ignored the per-form toggle entirely. The per-form address is now the first recipient candidate (then the older schema key, legacy key, global Notify address, admin email), and the per-form toggle overrides the global one when it has been explicitly set (`admin_notification_enabled()`; unset = inherit global, so existing forms are unchanged).
* Email Settings promised that a blank Sender name uses the site title and a blank Sender email uses the WordPress admin email, but `NotificationService::build_from_headers()` sent no From header unless a valid Sender email was set (so mail went out as "WordPress <wordpress@domain>", and a Sender name on its own was dropped). New `NotificationService::resolve_sender()` applies those defaults for every outbound mail; the Settings test email now uses the same resolver instead of its own partial copy.
* "View entry" links opened the inbox list instead of the entry: the admin-notification email (`NotificationService::get_entry_url()`) and the Analytics quiz-attempts table built `&entry=ID`, but the entries screen reads `entry_id`. Both now emit `entry_id` (plus `form_id` + `view=inbox` so the list behind the detail is scoped to the form).
* Quiz / poll "Randomize options" had no effect: the renderer emitted `data-quiz-randomize` but nothing consumed it (and the poll renderer ignored the setting entirely). Options are now shuffled server-side (works without JS) and re-shuffled per page load by `form-submit.js` (`initRandomizeOptions()`), so page caches don't freeze one order. Poll fieldsets gain `data-poll-randomize`.
* Entries keyboard shortcuts (r / u / s / # / !) acted on an internal focused row that was never highlighted and never followed the entry the user opened — focus defaulted to the first row and only moved with j / k, so opening entry 5 and pressing `#` trashed entry 1. Opening an entry now moves focus to it; while a detail is open every shortcut targets that entry; the focused list row shows a blue left marker and scrolls into view on j / k; trash / spam from the keyboard close the detail like the toolbar buttons do. Escape was handled by both the keyboard hook and the detail panel, calling `history.back()` twice — the hook now only clears the checkbox selection on the list and leaves closing to the panel.
* File upload: the 5 MB default never considered the host's PHP limit (`upload_max_filesize` / `post_max_size`, 2 MB by default), so on such hosts a 3 MB file passed the "Max 5 MB" hint and the client check, then failed with a generic "A file upload error occurred". The effective limit is now `min( field max_file_size, wp_max_upload_size() )` everywhere (hint, `data-max-size`, server check), `UPLOAD_ERR_INI_SIZE` / `UPLOAD_ERR_FORM_SIZE` return the field-level size message, and a multipart request that blows past `post_max_size` (PHP empties `$_POST`/`$_FILES`) gets a 413 size error instead of "X is required" for every field. New `SchemaHelper::file_size_limit()` is the single source of truth.
* Entries inbox: the list stopped at 50 rows with no way to reach older entries. A "Load more" control now appends the next 50 until every row matching the current view is shown, with a "Showing X of Y" count.
* Entries search: terms containing non-ASCII characters (e.g. "José") or slashes (URLs) found nothing because entry data was stored with escaped JSON. New entries are stored unescaped (`JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES`) and the search now matches both the raw and the escaped form, so existing entries are found too. Applies to CSV export with a search term as well.
* Rate-limit bucket is now keyed per form + IP instead of per IP site-wide.
* Honeypot check now runs before the rate-limit gate, so bot traffic no longer consumes attempts shared by real users on the same IP.
* A request with no usable `REMOTE_ADDR` is no longer exempt from the limit; such requests share one bucket.
* `neural_forms_rate_limit` filter now receives `$form_id` as a fourth argument.

### 1.1.2 - 2026-07-01

#### Fixed
* Multi-step forms no longer trigger an auto-scroll on page load.
* WordPress.org plugin directory now lists all four blocks (Form, Poll, Quiz, Multi-step).
* Field labels in the entry inbox no longer show raw slugs when a form was built without labels.
* "Analyze with Neural AI" now works on Lite installs without needing Pro.

#### Improved
* Form builder's Active status pill restyled — blue background with mint text.
* Clearer setup notices in the entry inbox — guide users to Settings when the API key or Neural AI toggle needs attention.
* Locked features in Lite now show a direct upgrade or setup link instead of a generic error.

### 1.1.1 - 2026-06-23

#### Fixed
* Front-end form assets (form-submit.js, form.css) were missing from the WordPress.org package, so form submission did not work for installs from WordPress.org. The assets are now included.
